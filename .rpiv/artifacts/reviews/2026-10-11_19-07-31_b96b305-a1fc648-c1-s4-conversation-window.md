### I3 🟡 Not-confirmed copy says "Try again" after an edit hides Try again

**Where**
`apps/desktop/src/renderer/conversation/save-outcome.ts:94` `apps/desktop/src/renderer/conversation/conversation-region.tsx:27` `apps/desktop/src/renderer/conversation/use-conversation-save.ts:101`

**Code**
```
  return readOnly && line?.tone === "unknown" ? { ...line, message: notConfirmedReadOnly } : line;
    tryAgain: !pending && !readOnly && kept?.tryAgain === true && conversation.resendable,
        : { ...memo, text, saveId: undefined, outcome: afterInput(memo.outcome) },
```

**Why**
Recovery availability is decided in three places with three inputs (load-notice.tsx:25 by status, save-outcome.ts:94 by tone and readOnly, conversation-region.tsx:27 by retryable and the kept saveId). After an uncertain save, editing the draft clears saveId (use-conversation-save.ts:101) and hides Try again, but on a read-write activation the line still says "The save could not be confirmed. Try again to check it." This is the recovery-affordance class that already needed follow-up fixes three times (43bc303, ca839da T6, ef3f92f F7).

**Fix**
Derive the not-confirmed copy from the same resendable flag that shows the button (rewrite the message whenever Try again is hidden, not only when readOnly), and add a renderer test: uncertain, then edit, then assert neither Try again nor its wording is shown.
