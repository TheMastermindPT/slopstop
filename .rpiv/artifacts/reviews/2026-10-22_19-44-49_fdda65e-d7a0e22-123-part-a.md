## 🟡 Important



### I1 🟡 Part A's typed shutdown and startup diagnostics are all discarded at the harness process edge

**Where**
`apps/harness/src/process-entry.ts:83`

**Code**
```
    failStartup("Harness received an invalid bootstrap message.");
```

**Why**
Part A builds distinct typed failures (RegistrationCleanupUnconfirmed with named parts, ApplicationDatabaseCloseUnconfirmed, HarnessRuntimeDisposeUnconfirmed, ordered AggregateErrors), but both edges keep only a code and a fixed text: apps/harness/src/process-shutdown.ts:19 calls failed("Harness shutdown failed.") without the value, and the startup catch logs every start or dispose failure as an invalid bootstrap message. Constituents Q24, Q26, Q27, Q33, Q34. A broken stop or start is never reported as clean (fatal code plus exit 1), so the core of degrade-distinguishes-broken holds; what is lost is every distinct diagnostic the slices added, and the field cannot tell a lost authority close from an unconfirmed listing cleanup.

**Fix**
Pass the failure value to the two fatal sinks and log a redacted summary (the failure _tag values and RegistrationCleanupUnconfirmed parts, never paths or messages), and give the startup catch a separate code for a runtime start or dispose failure versus an invalid bootstrap message. One small slice; the residuals W12 and W13 then shrink to the bound only.

### Q33 🟡 When the owner close outruns the 3 s shutdown budget, the observer's active Git inspections are never aborted

**Where**
`apps/harness/src/registration/registration-listing.ts:64`

**Code**
```
        duration: REGISTRATION_SHUTDOWN_CLEANUP_BUDGET_MS,
```

**Why**
The owner close drains preparations under its own 5 000 ms budget (apps/harness/src/registration/project-registration-preparation.ts:274-278), longer than REGISTRATION_SHUTDOWN_CLEANUP_BUDGET_MS = 3 000. The chain timeout then interrupts at :53, before observer.closeEffect (:54) starts, so apps/harness/src/project-registration-observer.ts:150 never aborts the running inspections, and the owner's distinct pendingCreation, pendingListing and pendingCleanup outcomes are folded into a bare 'listing' part. **Fix**
Start the observer close (or at least its abort signal) independently of the owner close, for example Effect.all over the three parts with explicit concurrency inside the one budget, or abort inspections first; keep the named parts from whatever finished.
