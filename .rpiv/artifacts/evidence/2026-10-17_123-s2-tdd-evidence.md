## Identity proof (at `7462116`, before any code change)

1. **The three copies are the same predicate.** Each is true exactly when the value is `instanceof ProjectStorageBrokenError` or `instanceof ProjectStorageUnavailableError`:
   - `isKnownStorageError`, `project-storage-node-errors.ts:37-42`: `if (error instanceof ProjectStorageBrokenError) return true; return error instanceof ProjectStorageUnavailableError;`. Its only caller is `storageFailureFor` (:67).
   - `isStorageFailure`, `project-storage-node-registry.ts:60-64`: `error instanceof ProjectStorageBrokenError || error instanceof ProjectStorageUnavailableError`. Its only caller is `keepStorageFailure` (:76).
   - the inline pair in `markerQueryFailure`, `project-storage-upgrade-node-adapter.ts:558-559`: each branch returns `error` as is, so together they are "return `error` when the guard holds".

   `rg -n "isKnownStorageError|isStorageFailure" apps` finds only those definitions and the two callers.
2. **No custom `Symbol.hasInstance`.** `rg -n "hasInstance" apps packages` finds nothing. The two classes (`project-storage-errors.ts:1-7`) and their only subclasses define none:
   - `ProjectStorageApplicationClientInitializationError` (`project-storage-errors.ts:12`);
   - `ProjectStorageUpgradeBusyError` (`project-storage-upgrade.ts:18`).

   `rg -n "extends (ProjectStorage\w*Error)" apps packages` finds only these two. The union of the three copies is therefore one predicate, and no consumer loses or gains a case.
3. **Not copies.** `rg -n "instanceof ProjectStorage(Broken|Unavailable)Error" apps/harness/src` lists every class test. Apart from the three copies, each one uses a different vocabulary, so all are out of scope:
   - single-class tests: rethrow Broken (`database-schema-verifier.ts:563`, `generated-migration-resources.ts:428`, `project-storage-file-adapter.ts:260`), plus `project-storage-transaction.ts:84`, `project-storage-node-adapters.ts:175`, `project-storage-store.ts:145`, `project-storage-upgrade-verification.ts:138` and `project-storage-upgrade-recovery.ts:68`;
   - `project-storage-application-client.ts:77-80`: Unavailable, or an unavailable code;
   - `isBusyStorageError` (`project-storage-node-errors.ts:51-61`): Unavailable, or a busy code, or a busy cause;
   - the status mappings, which test ClientInitialization first and map each class to its own status: `project-storage-store.ts:493-499, 543-551` and `project-storage-upgrade-pipeline.ts:466-476`;
   - `isDefiniteSchemaMismatch` (`application-database-migration.ts:311-312`): Broken with no cause.
   - the test files only use the class as a type guard.
4. **Order kept.** In `markerQueryFailure`, the pair runs before `isBusyStorageError` (:560). The migrated guard takes the pair's place, so a typed Unavailable (`ProjectStorageUpgradeBusyError` included) still passes through as is and is never wrapped as busy again.
