## Fix after the candidate report (decisions log §123): remove the equivalent guards

The coordinator chose option (b): remove the redundant injected check, so P-M (no pre-registered survivors) holds; and check the removal guard the same way. A new commit on `509b205`, with no amend.

- **The injected check (`registry-database.ts:81` at `509b205`).** I1 had already shown it equivalent: 8/8 green without it (above). `applicationDatabaseFor` returns an injected authority without writing the WeakMap, so for injected options the map has no entry. **Removed.**
- **The removal guard (:87 at `509b205`, `if (standaloneAuthorities.get(options) === authority)`).**
  - Binding observation: an unconditional delete (mutant U, blob `9fd3fe14…`) stays green, 8/8 on `registration-registry.test.ts`.
  - It also passed a scratch probe (`s4/zz-scratch-s4.test.ts`, kept outside the repository) for the only interleaving that could replace the entry during the stop. That is several `registry.stop()` calls on one registry awaiting the same memoized authority stop, while the first caller creates a fresh authority (`applicationDatabaseFor`) as soon as its stop resolves. Rows: `lease false` and `lease true` with fake timers, and three stops with real timers; 3/3 green under U and under the guard.
  - The fibers waiting on the one memoized stop all run their finalizers before the first caller's continuation can run. Until the delete, `applicationDatabaseFor` returns the existing entry, and only this function deletes it. So no path replaces the entry during the stop, and the guard's mutants are equivalent.
  - **Simplified** to `Effect.sync(() => standaloneAuthorities.delete(options))`.
  - Residual: this rests on the observed ordering of the Effect fibers, not on a guarantee written in the code.
- **TSDoc** updated: the injected authority is never in the map, so it is left alone.
- **Re-checks on the new source** (blob `92916c20…`, tree `9a6dbf15aadabf0e`, restored by copy after each run):
